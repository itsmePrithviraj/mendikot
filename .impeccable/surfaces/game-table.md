# Game table — approved direction

Mode: Operate with a tactile tabletop character.

Visual authority: the user approved the conversation's portrait two-row and landscape single-row code mockups and asked to use them for implementation. Build directly from those layouts; AI reference images are a future input, not a prerequisite or an approved pixel specification.

First viewport: Mendikot wordmark on a quiet warm surround. Green table contains a compact practice label, team tens and hukum, partner opposite, opponents on each side, a central trick, and the player's ivory hand. Actions remain attached to the hand. No dashboard panels, betting economy, or fake social presence.

Signature interaction: cards are shuffled and dealt into the hand, selection lifts one card, confirmation plays it toward the middle, and the winning trick is held briefly before collection. Motion is optional and cannot control rule execution.

Responsive contract: upright phones use two hand rows; phones under 360px use three readable rows; wide/landscape windows use one row. No screen lock. Game state survives resize and refresh. Five-card trump selection remains visible before the remaining eight cards arrive. Desktop uses larger cards and breathing room rather than extra interface panels.

Type and material: DM Sans for information, Cormorant Garamond for rank and display. Forest felt, warm ivory faces, oxblood red suits, restrained brass. Geometric woven back pattern. A tiny sheep adds personality to 10s without replacing 10 or suit. Preserve numeric 10; no word TEN.

Scope: local practice versus three openly labeled bots, complete game, rules/settings, save/restore, PWA installation and offline support. Online rooms and store binaries are separate milestones.

Acceptance: both hukum modes, turn/follow-suit legality, scoring/tie handling, selection/confirmation, reduced motion, responsive table at portrait/landscape/desktop, no overflow of essential controls, persistence and offline continuation. No claimed human/device comfort study.
